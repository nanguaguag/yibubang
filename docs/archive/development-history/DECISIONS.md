## ADR-01: 内容只读与用户可写物理分离架构

### 1. 决策背景
在早期版本中，题目、科目、章节、评论以及答题数据集中在一个庞大的单体 SQLite 数据库（`question_data.sqlite`，~287MB，14.2 万道题）。
存在致命瓶颈：
1. 任意题库修正错别字，用户必须重新全量下载 60MB+ 的压缩包；
2. 口腔、临床、护理强行绑定，无法按需下载或扩展；
3. 用户刷题数据与题库内容混在同一库中，更新题库极易覆盖或损坏用户历史进度。

### 2. 决策内容
- **物理分离**：所有专业题库（`QuestionBank/<bank_id>/<bank_id>.sqlite`）在客户端**仅以只读模式（`readOnly: true`）打开**，更新采用文件原子替换。
- **用户状态独立**：用户的答题记录、历史答案、对错状态、收藏、斩题、做题耗时与笔记一律写入独立的 `user_data.sqlite`。

### 3. 替代方案评估
- *方案 A：继续使用单库，通过 SQL UPDATE 脚本打补丁* —— 被否决。补丁链条极长，断网或崩溃易导致数据库状态处于半损坏状态，灾难恢复成本不可控。

## ADR-02: 全局稳定 `question_id` 契约

### 1. 决策背景
医学考试题目（真题与模拟题）在不同考试分类中高度重合（例如“临床执业医师”与“临床期末考试”存在大量完全相同的历年真题）。

### 2. 决策内容
- 题目实体跨题库唯一，`question_id` 全局稳定。
- 用户在任一题库作答某道题后，切换到包含该题的其他题库时，**自动共享同一份作答与收藏状态**，用户无需在不同题库重复刷同一道题。
- `user_data.sqlite` 中的 `Question` 表主键必须且只能是单列 `id`。

### 3. 约束后果
- 题库维度隔离仅限于物理文件、目录记录（`QuestionBank`）以及分题库课程/章节对错计数（`IdentitySubject`、`IdentityChapter`），禁止将 `bank_id` 加入 `Question` 表的主键。

## ADR-03: 文件指纹持久化缓存取代启动全库完整性扫描

### 1. 决策背景
SQLite 的 `PRAGMA integrity_check` 是全库全表扫描操作。对 176MB 的百兆级 SQLite 执行该命令，在低端 Android 机型上需耗时 2~5 秒，严重阻塞冷启动。

### 2. 决策内容
- 首次全量校验通过后，计算题库文件的指纹字符串：`"${stat.size}:${stat.modified.millisecondsSinceEpoch}"`。
- 将已通过校验的指纹与元数据持久化存储至 `SharedPreferences`。
- 二次启动或切换题库时，先比对文件大小与修改时间戳，若一致则**直接跳过 `PRAGMA integrity_check`**，耗时低于 5ms。

### 3. 容灾策略
- 一旦用户重新下载、覆盖或导入新题库，文件修改时间或大小改变，指纹自动失效，重新触发严格的 5 重全量校验。

## ADR-04: 基于 SQLite `ATTACH DATABASE` 的高性能跨库进度自愈

### 1. 决策背景
当用户导入数据、题库升级或出现进度异常时，需要根据用户库中的 `Question` 重新计算各个课程和章节的做对/做错数字。如果在 Dart 内存中遍历数十万题目循环匹配，会导致长时间的主线程卡死。

### 2. 决策内容
- 在 `lib/db/data_transfer.dart` 中使用 SQLite 原生 `ATTACH DATABASE`，将只读题库以 `qbank` 别名挂载到用户库连接上；
- 通过一条带 `GROUP BY` 的高性能 SQL 直接完成 `IdentityQuestion` 与 `Question` 的关联聚合并执行 `UPSERT`；
- 执行完毕后立即 `DETACH DATABASE qbank`。

## ADR-05: 增量双向同步的时间戳仲裁 (LWW) 与离线队列

### 1. 决策背景
用户可能在手机和电脑等多端离线刷题，随后接入网络进行同步，存在并发状态冲突（如端 A 重做了本章 status=0，端 B 做了新题）。

### 2. 决策内容
- **状态表 (Question)**：引入毫秒级 `updated_at` 字段，采用 LWW（Last-Write-Wins，最后写入者胜出）算法。
- **流水表 (Activities)**：作为 Append-Only 事件溯源表，按主键防碰撞 ID 去重追加，不丢失任何作答记录。
- **离线同步守护**：医考帮作答与笔记上报统一入本地 SQLite 队列，后台顺序消费并具备重试计数保护，防止队头阻塞。

## ADR-06：来源配置、更新发现与安装任务分离（2026-11-07）

当前实现 Commit f011283；详细契约见 QUESTION_BANK_MANAGEMENT_DESIGN.md。

来源 URL 去重，bank_id 标识题库，来源绑定独立于内容版本。保存只写配置，全局/单库检查共用 check 且不安装。不同 URL 提供同 bank_id 保留为候选，来源编辑先保留旧绑定，检查匹配后显式切换；一个来源失败不取消其他结果。官方来源也使用同一模型。

JSON 发布清单负责轻量版本发现；直链用 HEAD/条件请求，不足以确定内容时返回需下载确认。下载为独立任务，包经摘要/SQLite 校验后进入有界持久化缓存，运行期租约防 LRU 清理。同一任务复用确认、比较和安装产物；显式重新下载绕过缓存。HTTP 验证器按实际传输地址保存。

用户库 v13 BankContentState 记录最近处理的上游发布与本地修订，不把合并文件 hash 不同直接视为上游更新。合并也推进基线，同发布不重复安装；本地有补充、基线未知、同版本变更或版本回退均需显式处理。自动检查与自动安装独立，自动安装只接受已知基线且无本地补充的安全前进版本。

沿用只读正式库、原始全局 question_id 和 SQLite ATTACH；合并只写暂存，目录/基线/履历/ATTACH 统计共用事务并回滚。拒绝更改已安装学科的来源。UI 使用项目 Material 卡片体系与单一状态动作，完整性只读扫描和重新下载独立进入详情更多菜单。
