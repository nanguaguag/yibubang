# 医考帮题库「智能增量同步」设计与实现

## 1. 背景

本地题库（clinical_final）是从旧版数据构建的，章节 ID / 章节拆分方式与当前医考帮官方接口并不一致。例如：

- 本地 `45000 = 绪论`，18 题；官方 `45000 = 绪论`，32 题 → 需要补 14 题。
- 本地 `45011 = 脉管系统 第十一章 心血管系统`；官方 `45011 = 泌尿系统 第十一章 肾`。
- 本地 `45020 = 神经系统 第二十章 ...`；官方 `45020 = 脉管系统 第二十章 心血管系统`。

因此**不能按 chapter_id 直接整章覆盖**，否则会把“心血管系统”和“肾”混在一起，甚至删掉用户已经做过的题。

原来的「从医考帮官方同步题库到本地」会逐章重新拉取全部 1172 章、重建整个题库，耗时长、请求量大、容易触发风控。

## 2. 目标

- 只拉**有变化**的章节，而不是全量 1172 章。
- 静默：启动后后台分批执行，不弹窗、不阻塞刷题。
- 原子：更新失败时旧题库保持可用；成功时一次性替换。
- 哈希校验：章节内容哈希、清单哈希、最终题库文件 SHA-256。
- 风控友好：随机抖动、每轮请求预算、失败指数退避、无权限章节跳过。
- 可续传：应用退出/崩溃后从上次进度继续。
- 不破坏本地进度：只新增/更新内容，绝不因为远端列表缺题就删除本地题。

## 3. 数据链路

1. `GET /allQuestion/question/subjectV2`：身份树。
2. `POST /allquestion/question/chapter`：每个叶子身份的章节目录（含 `chapter_id`、`count`、`updated_at`）。
3. `POST /allquestion/question/list`：按章节拉取全部题目（DES 解密）。

目录阶段只有 1 + N(叶子身份) 次请求（临床为 1+4=5 次），不再逐章请求。

## 4. 增量选择

持久化两张状态表（用户库 v11）：

- `YkbBankSyncState`：每个题库一条，保存 manifest 哈希、待处理队列 JSON、上次同步时间、失败次数、退避时间、上次题库哈希等。
- `YkbBankChapterState`：每个远端章节一条，保存远端 identity/subject/title/count/updated_at、内容哈希、映射到本地 chapter/subject、匹配方式、额外本地题数、上次同步时间。

选择规则：

- 章节状态存在，且 `remote_count` / `remote_updated_at` 与本次一致 → 跳过。
- 无状态，且**同 ID + 同标题 + 同题量 + 远端未在题库生成后更新过** → 直接 bootstrap，不请求。
- 其他情况 → 进入待处理队列。
- 当前正在做的章节（`lastChapterId`）优先；其次同 ID 同标题、标题匹配、其余按更新时间倒序。
- 每批默认 12 章（手动 16 章），请求预算 28 次/轮。
- 队列写入 `pending_json`，失败/未处理章节保留，下次继续。

## 5. 语义映射（关键）

拉取到某一远端章节的题目后，按以下优先级决定写入哪个本地章节：

1. 状态里已有的 `local_chapter_id`（且本地仍存在）。
2. **同 ID + 归一化标题相同**（例如远端 45000 绪论 → 本地 45000 绪论）。
3. 归一化标题唯一匹配（去掉“第 X 章/节/篇”、空格、标点后比较）。
4. 同科目 + 标题相似度 ≥ 0.86（LCS 比率）。
5. **题目 ID 重合度**：远端题目 ID 有多少已存在于本地某章节；要求重合 ≥ 5 且 ≥ min(本地题数, 远端题数) 的 30%。
6. 以上都不满足 → 新建本地章节：
   - 远端 ID 未被本地占用则复用，否则生成 `ykb_<远端ID>_<标题哈希8>`，避免和语义不同的旧章节撞 ID。
   - 科目按 ID/名称匹配；冲突时生成 `ykb_sub_...` 合成 ID。

映射方式记录在 `match_method`：`state / id-title / title / title-subject / fuzzy / overlap / new / restricted`。

## 6. 合并策略

对每个远端题目：

- 本地不存在 → 插入 `Question` + `IdentityQuestion`。
- 本地已存在且内容哈希不同 → 更新题目内容字段。
- 本地已存在且内容相同 → 只补 `IdentityQuestion` 关联。
- 远端没有但本地有 → **保留**，不删除；记录 `extra_count`。
- 题库文件里的 `cut_question/user_answer` 统一写 `0/''`，账号状态只存在用户库，不污染共享题库。

内容哈希：

- 单题：对 `questionRow` 的字段（排除章节/身份归属、cut/user_answer）排序后 SHA-256。
- 章节：按题目 ID 排序，拼接 `id|单题哈希`，再加远端章节 ID，SHA-256。
- manifest：按章节 ID 排序，拼接 `id|identity|count|updated_at`，SHA-256。
- 最终题库：`QuestionBankRepository.importFile` 对文件字节做 SHA-256，写入 `QuestionBank.content_hash`。

## 7. 原子安装

1. 复制当前题库文件到同目录 staging：`<bankId>.delta-<ts>.sqlite`。
2. 打开 staging，在**一个事务**内完成本批所有章节的插入/更新/统计回填、`BankMeta` 计数/版本更新。
3. `PRAGMA integrity_check`、`PRAGMA foreign_key_check`、计数与 `BankMeta` 交叉校验。
4. 调用既有 `QuestionBankRepository.importFile`：
   - 重新校验 schema；
   - 计算文件 SHA-256；
   - 旧文件改名 `.bak`；
   - staging 原子 rename 到正式路径；
   - 更新 `QuestionBank` 的 version/content_hash/size/updated_at；
   - 任一步失败自动回滚旧文件。
5. 只有安装成功后才写入章节状态；失败时旧题库和旧状态都保持，指数退避后重试。

## 8. 风控/静默

- 每次请求前 1.2–3.2 秒随机抖动。
- 每轮最多 12 章 / 28 请求。
- 启动后延迟 15–35 秒再开始；每批之间约 4 分钟；应用关闭后下次启动续传。
- 接口 `code=203（警告，无查看权限）`：标记 `restricted`，7 天内不再请求，避免反复撞接口。
- 网络/309/其他错误：保留 pending，`failure_count` 指数退避（15 分钟起，上限 24 小时）。
- 手动按钮可立即执行一批（16 章），自动开关默认开启。

## 9. 实测结果（用户当前数据）

以本地 `45000 绪论 18 题`、官方 32 题为例：

- 第一批 12 章：更新 `45000` 成功；新增 14 题、更新 18 题内容、保留本地额外 1 题；跳过 11 个无权限章节。
- 本地 `45000` 关联题数：18 → **33**（官方 32 + 本地已作答的旧题 `588680`，保留以免丢进度）。
- 题库总数：57346 → 57360；`IdentityQuestion`：57346 → 57361。
- `BankMeta` 计数与实际一致；`integrity_check = ok`；`foreign_key_check` 为空。
- 用户库做题记录不变：20 已答 / 24 流水。
- 题库版本：`3.0.0+delta.<时间戳>`（实测 `3.0.0+delta.1793375279`，语义化版本保证不会被旧的 3.0.0 远端包判定为可更新），`QuestionBank.content_hash` 已更新，安装状态 `installed`。
- 同步后 `QuestionBank.update_enabled=0`，避免题库管理页用旧的 3.0.0 包覆盖官方 API 增量；需要换回官方包时可手动执行「全量重建」或重新启用远端更新。
- 剩余 793 章在后台队列中，分轮继续；无权限章节 7 天后重试。

## 10. 已知取舍 / 后续

- 本地章节结构仍是旧结构，官方新拆分出来的章节会映射到最接近的旧章节或新建章节；只有做一次「全量重建」才能得到纯官方章节树。
- 本地已有的额外题不会自动删除（尤其是用户已做过的题）；如果希望严格对齐官方题量，可后续加“清理未作答的本地额外题”选项。
- 首次追赶队列较大（约 800 章）时，需要应用累计运行数小时；这是为了避免一次性请求风控。已处理章节不会重复请求。
- 无权限（203）章节不会拉取；如果账号权限变化，7 天后自动重试。
- 后续可扩展：远端清单缓存到服务端、章节内容哈希上传做跨设备校验、并行度可配置、影子官方题库全量重建（完成后原子切换）。
- 智能同步后的题库版本使用 `3.0.0+delta.<ts>` 并关闭远端包更新（`update_enabled=0`），防止题库管理页用旧的 3.0.0 包覆盖增量内容。

## 11. 代码位置

- `lib/services/ykb_bank_smart_sync_service.dart`：增量同步核心。
- `lib/services/ykb_bank_sync_service.dart`：暴露 `fetchChapterQuestionsResult` / `questionRow`，供增量与全量共用。
- `lib/db/database_helper.dart`：用户库 v11，新增两张同步状态表。
- `lib/main.dart`：启动静默同步 + 4 分钟续传。
- `lib/screens/my_page.dart`：登录后触发一批。
- `lib/screens/settings_page.dart`：智能同步入口、自动开关、全量重建入口。
